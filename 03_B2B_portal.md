# ТЗ v2.0 — Том 3. Портал партнёра (B2B)

**Модуль:** C
**Аудитория:** генподрядчики, строительные компании, монтажные и промышленные организации — люди **со специальными знаниями**
**Референс:** app.fieldwire.com (структура «проект → задачи → планы → фото → отчёты»), адаптированный под аренду техники
**Стратегическая роль:** портал — главный «замок». Клиент, у которого в Dimecon живут его проекты, история смен, фотоархив, договорные ставки, документы и интеграция с ERP, **не уходит к конкуренту из-за скидки в 3 %.**

---

## 3.1. Принципы проектирования портала

1. **Плотность вместо воздуха.** Это рабочий инструмент, а не витрина. Таблицы плотные, на экране максимум информации, минимум прокрутки.
2. **Скорость создания заявки — главная метрика.** Целевое: **≤ 30 секунд** для повторной типовой заявки, ≤ 90 секунд для новой.
3. **Проект — корневая сущность.** Не заказ, не техника. Всё группируется вокруг объекта строительства, потому что так устроено мышление прораба.
4. **Ни одного вопроса, ответ на который уже есть в системе.** Адрес, контакты, условия площадки, предпочитаемая техника — подставляются из проекта.
5. **Никакой маркетинговой воды.** Внутри портала — только факты, цифры и действия.
6. **Мобильный равноценен десктопу**, а для смен и фото — первичен.
7. **Партнёр видит ровно то же, что диспетчер** (в части своих заказов). Отсутствие «двух правд» — фундамент доверия.

## 3.2. Онбординг партнёра [M]

### 3.2.1. Путь от заявки до рабочего аккаунта

```
Лендинг /parteneri
  → Форма «Получить доступ» (компания, IDNO, контакт, сфера, ориентировочный объём)
  → Автописьмо + задача менеджеру (SLA 4 рабочих часа)
  → Менеджер верифицирует, заводит partner, назначает прайс-лист, лимит, отсрочку, уровень
  → Инвайт на e-mail администратора партнёра
  → Активация: пароль/OTP, подтверждение реквизитов, загрузка договора
  → Мастер первого проекта (3 шага) → приглашение коллег
  → Портал готов к работе
```

**Требование [M]:** от заявки до работающего кабинета — **не более 1 рабочего дня**. Каждый час задержки — вероятность, что прораб позвонит конкуренту.

### 3.2.2. Мастер первого проекта [S]

Три шага, чтобы партнёр сразу увидел ценность:
1. Название объекта и адрес (на карте).
2. Период и ответственный прораб.
3. «Что понадобится в ближайший месяц?» — чекбоксы типовой техники → сразу формируется черновик графика потребности.

По завершении — заполненный проект, а не пустой экран. **Пустой экран после онбординга — главная причина, по которой B2B-порталы умирают.**

### 3.2.3. Лендинг `/parteneri` [M]

Строится по модели Odoo: боль → решение → доказательство → CTA.

Обязательные блоки:
- H1 с ценностью для подрядчика: «Вся техника на ваших объектах — в одном окне»
- 6 болей подрядчика с ответами: «сорванный график», «спор о часах», «не знаю своих ставок», «бухгалтерия ждёт акты», «прораб не дозвонился», «нет истории по объекту»
- Скриншоты портала (реальные, не макеты)
- Таблица уровней партнёрства и что даёт каждый (Том 4 §4.4)
- Расчёт экономии: калькулятор «сколько вы тратите на технику в год → сколько сэкономите на уровне “Золото”»
- Отзывы партнёров с именами и объектами
- CTA «Получить доступ» + «Записаться на демо (20 минут)»

## 3.4. Экран «Обзор» (дашборд партнёра) [M]

Верх — **строка действий, требующих внимания** (то, из-за чего партнёр заходит в портал):

| Карточка | Содержание | Действие |
|---|---|---|
| Требуют подтверждения | N сменных рапортов | «Подтвердить все» / по одному |
| Ждут вашего ответа | N КП со сроком действия | «Посмотреть» |
| Просроченные счета | сумма, количество | «Оплатить/скачать» |
| Сегодня на объектах | N единиц техники | «Смотреть график» |
| Ближайшие подачи | список на 48 ч с ETA | «Карта дня» |

Ниже — виджеты:
- **Календарь-лента на 14 дней** с подачами по проектам
- **Расход за месяц** vs предыдущий, с разбивкой по проектам (столбики)
- **Топ техники** по часам за период
- **Простои** и их причины (если есть — с суммой потерь; честный показ даже невыгодных компании данных = доверие)
- **Ваш уровень партнёрства**: текущий, оборот, сколько до следующего уровня и что он даст (**прямая механика удержания, см. Том 4**)
- Лента активности проектов

## 3.5. Проекты [M]

### 3.5.1. Список проектов

Представления: карточки / таблица. Колонки: название, адрес, статус, период, техника сейчас, открытые заявки, часы за месяц, сумма за месяц, ответственный. Фильтры и сохраняемые пресеты фильтров [S].

### 3.5.2. Карточка проекта — вкладки

#### Вкладка «Обзор»
Сводка: адрес с картой, период, ответственные (со стороны партнёра и Dimecon — **с фото и телефоном диспетчера, закреплённого за проектом**), KPI (часы, сумма, число заявок, простои), ближайшие подачи, лента активности, закреплённые файлы (ППР, схемы).

**Закреплённый диспетчер [S]** — важная механика: у партнёра есть «свой человек» в Dimecon с именем и лицом. Это резко снижает вероятность ухода.

#### Вкладка «Заявки» [M]

Три представления одних данных, переключаются одной кнопкой:

**Список** — плотная таблица: № · тип · техника · дата и время · длительность · статус · автор · сумма. Массовые действия: дублировать, отменить, экспортировать.

**Канбан** — колонки по статусам: Черновик · Отправлена · На рассмотрении · Подтверждена · Запланирована · Выполняется · Завершена. Drag-and-drop ограничен (партнёр может только отменять и отправлять; подтверждение — за Dimecon).

**Календарь** — месяц/неделя/день, заявки как события, цвет по статусу.

**Создание заявки [M] — центральный сценарий портала.**

Форма в одной модалке, без визарда (аудитория знает, что ей нужно):

| Поле | Поведение |
|---|---|
| Проект | предзаполнен |
| Тип | кран / транспорт / услуга |
| Техника | выбор конкретной единицы **или** «подберите сами по параметрам» (Q/R/H) |
| Дата и время | с календарём доступности выбранной техники |
| Длительность | часы/смены |
| Место на объекте | выбор пина с плана или ввод |
| Груз/задача | краткое описание + вес |
| Условия | чекбоксы (как в B2C, но без пояснений) |
| Контакт на месте | из участников проекта |
| Комментарий | |

**Ускорители [M]:**
- **Шаблоны заявок**: «Кран на бетонирование, вторник 8:00, 8 ч» — сохраняется и применяется одним кликом.
- **«Как в прошлый раз»** — копия последней заявки проекта.
- **Повторяющиеся заявки** — «каждый вторник в течение 6 недель» с превью всех дат и возможностью исключить отдельные.
- **Массовое создание** — загрузка графика потребности CSV/XLSX [S].

Замер приёмки: **повторная заявка — ≤ 30 секунд, включая подтверждение.**

#### Вкладка «План объекта» [M, MAX]

Модель Fieldwire, адаптированная под технику.

- Загрузка подложки: PDF (многостраничный), PNG/JPG, либо **спутниковый снимок участка** с карты.
- Просмотр: зум/пан (OpenSeadragon/pdf.js), поворот, измерение расстояний по заданному масштабу [S].
- **Пины** с типами:

| Тип пина | Смысл | Данные |
|---|---|---|
| `crane_setup` | точка стоянки крана | покрытие, ширина подъезда, уклон, фото |
| `pickup` | откуда берём | — |
| `drop` | куда ставим | — |
| `obstacle` | препятствие | высота, описание |
| `power_line` | ЛЭП | напряжение, высота — **автоматически помечает заявку как требующую согласования** |
| `entrance` | въезд на объект | ширина, ограничение по высоте, режим доступа/пропуска |
| `storage` | зона складирования | — |
| `hazard` | опасная зона | — |

- Пин связывается с заявкой: диспетчер и оператор получают точку и фото **до выезда** — это напрямую сокращает время на объекте и число сорванных подач.
- Версионирование планов, пометка актуальной версии, история.
- Комментарии к пину с упоминанием участников [S].

**Ценность для удержания:** один раз размеченный объект экономит время при каждой следующей заявке. Переносить эту разметку к конкуренту невозможно.

#### Вкладка «График техники» [M]

Timeline (resource-view): строки — единицы техники, ось — время (день/неделя/месяц).

- Цветовая кодировка статусов: запрошено, подтверждено, выполняется, завершено, конфликт.
- Отображаются **только свои** брони + агрегированная доступность парка («свободно 3 автокрана» без раскрытия чужих заказов) — коммерческая тайна других клиентов защищена [M].
- Drag-and-drop = **запрос на перенос**, а не перенос: создаётся `change_request`, который подтверждает диспетчер.
- Конфликты и предупреждения подсвечиваются: «на 24.09 у вас две заявки на один кран».
- Экспорт графика в PDF/PNG для планёрки [S].

#### Вкладка «Смены и рапорты» [M, MAX]

Основной источник финансовой правды и главный источник конфликтов в отрасли — поэтому проработан максимально.

**Сменный рапорт** содержит: дата, техника, оператор, время прибытия/начала/окончания/убытия, часы работы, часы простоя с причиной, число подъёмов, показания моточасов/одометра, выполненные работы, фото (обязательность настраивается), примечания, подпись оператора, подпись представителя заказчика.

**Поток:**
```
оператор заполняет (мобильно, в т.ч. офлайн)
  → submitted            партнёр получает push/e-mail
  → approved             прораб подтвердил (в 1 клик)
  или → disputed         прораб оспорил с указанием, что не так
      → диспетчер разбирает → corrected → повторно на подтверждение
  → закрытие: рапорт становится основанием для акта и счёта
```

**Требования [M]:**
- Подтверждение доступно **в день смены**, напоминание через 24 ч, автоподтверждение через 72 ч (настраивается партнёром, по умолчанию — да, с явным уведомлением).
- При споре — видна вся история изменений и фото с таймстемпами.
- Партнёр видит **накопленные часы по проекту в реальном времени**, а не узнаёт сумму в конце месяца.
- Электронная подпись представителя: рисование пальцем на телефоне или подтверждение кодом [S].

**Ценность:** «мы больше не спорим о часах» — самый частый аргумент, который партнёр называет, объясняя, почему работает именно с этой компанией.

#### Вкладка «Файлы» [M]
Документы проекта: ППР, схемы строповки, разрешения, акты, фотоархив. Папки, поиск, версии, права на уровне проекта, предпросмотр, массовое скачивание ZIP.

#### Вкладка «Команда проекта» [M]
Участники со стороны партнёра (роли), контакты Dimecon (закреплённый диспетчер, операторы на объекте сегодня), настройки уведомлений по проекту.

## 3.6. Сквозные разделы

### 3.6.1. Заявки (все проекты) [M]
Единый список по всем проектам с фильтрами: проект, статус, тип, техника, период, автор. Сохраняемые фильтры, экспорт.

### 3.6.2. Смены (все проекты) [M]
Реестр всех смен с фильтром «требуют подтверждения» по умолчанию. Массовое подтверждение выделенных [S]. Экспорт табеля в XLSX для бухгалтерии.

### 3.6.3. Документы [M]
КП, договоры, приложения, акты, счета, путевые/сменные рапорты, разрешения. Фильтры по типу/периоду/проекту, массовое скачивание, статус подписания [S: ЭЦП].

### 3.6.4. Счета и финансы [M]

- Список счетов: № · дата · сумма · оплачено · остаток · срок · статус (выставлен / частично / оплачен / **просрочен**).
- Баланс и кредитный лимит: использовано / доступно, прогресс-бар, дата ближайшего платежа.
- Сверка взаиморасчётов за период — сформировать PDF/XLSX.
- Оплата по счёту: реквизиты, QR/платёжная ссылка [S], загрузка платёжного поручения.
- **Депозитный кошелёк** [C, MAX]: партнёр пополняет баланс авансом, заказы списываются автоматически, за депозит — бонусная ставка. Сильный финансовый «замок».
- Интеграция e-Factura [S].

**Требование прозрачности [M]:** каждая строка счёта кликабельна и раскрывается до сменного рапорта и заявки, породивших её. Ни один партнёр не должен спрашивать «а за что это?».

### 3.6.5. Каталог с договорными ценами [M]

Тот же парк техники, но:
- **договорная ставка вместо «от»** — партнёр видит свою цену;
- реальный календарь доступности;
- кнопка «Забронировать» прямо из карточки;
- сравнение техники;
- скачивание паспортов и грузовых характеристик (PDF) — то, что прораб реально ищет;
- пометка «вы уже использовали эту машину на объекте X» [S].

### 3.6.6. Аналитика партнёра [S, MAX]

Отчёты с фильтрами по периоду и проектам:
- расходы по месяцам и проектам (динамика);
- структура затрат: работа / подача / допуслуги / простои / перепробег;
- часы по типам техники;
- **простои и их причины** — сколько денег потеряно и по чьей вине (включая вину Dimecon — показываем честно);
- средняя стоимость часа по проекту;
- сравнение периодов, план/факт по бюджету объекта [C];
- экспорт XLSX/CSV, автоматическая отправка отчёта на e-mail раз в месяц [S].

**Ценность для удержания:** портал становится инструментом, из которого партнёр берёт цифры для собственной отчётности. Уйти = потерять источник данных.

### 3.6.7. Команда [M]
Приглашение сотрудников по e-mail с ролью, управление доступом к проектам, деактивация, журнал действий сотрудников [S].

### 3.6.8. Настройки партнёра [M]
Реквизиты, контакты, адреса, логотип (для документов) [S], язык по умолчанию, уведомления по каналам и событиям, правила автоподтверждения рапортов, API-ключи, вебхуки.

## 3.8. Мобильный режим и офлайн (PWA) [S, MAX]

### 3.8.1. Экран «Сегодня» (мобильная главная)
- Что подаётся сегодня: техника, время, оператор с фото и кнопкой «Позвонить».
- Кнопка «Техника приехала» / «Начали работу» [S] — фиксация фактического времени с геометкой.
- «Подтвердить рапорт» — крупной кнопкой.
- «Добавить фото» — камера в один тап, фото привязывается к смене и проекту.
- «Новая заявка» из шаблона.

### 3.8.2. Офлайн-механика [M для PWA]

| Данные | Поведение офлайн |
|---|---|
| Планы объекта и пины | кэшируются, доступны для просмотра |
| Открытые заявки и смены проекта | кэшируются (последние 30 дней) |
| Черновик рапорта | заполняется офлайн, ставится в очередь |
| Фото | сохраняются локально (IndexedDB), выгружаются при сети, с прогрессом |
| Новая заявка | ставится в очередь, помечается «будет отправлена» |
| Подтверждение рапорта | ставится в очередь |

**Синхронизация [M]:**
- очередь с экспоненциальными ретраями;
- индикатор состояния («3 действия ожидают отправки»);
- конфликт разрешается правилом «сервер выигрывает, локальная версия сохраняется как черновик + уведомление»;
- идемпотентность по клиентскому UUID — повторная отправка не создаёт дубль;
- фото сжимаются на клиенте до 1920 px по длинной стороне перед отправкой (экономия трафика на объекте).

## 3.10. API для партнёров [S, MAX]

### 3.10.1. Назначение
Интеграция с ERP/системами планирования партнёра. **Самый прочный замок удержания:** после интеграции переход к конкуренту требует ИТ-проекта.

### 3.10.2. Аутентификация
API-ключ (`X-API-Key`) + HMAC-подпись тела (`X-Signature`, SHA-256) и `X-Timestamp` (окно 5 мин) **либо** OAuth2 client_credentials [O-3.2]. Ключи выпускаются администратором партнёра, ротация, ограничение по IP [S], журнал вызовов.

### 3.10.3. Эндпоинты

```
GET    /api/v1/equipment                         каталог с ТТХ и договорными ценами
GET    /api/v1/equipment/{id}                    карточка
GET    /api/v1/equipment/{id}/load-chart         грузовые характеристики
GET    /api/v1/equipment/{id}/availability?from=&to=
POST   /api/v1/quotes                            предварительный расчёт (тот же движок)
GET    /api/v1/projects                          проекты партнёра
POST   /api/v1/projects                          создать проект
GET    /api/v1/projects/{id}
POST   /api/v1/projects/{id}/orders              создать заявку
GET    /api/v1/orders?status=&from=&to=
GET    /api/v1/orders/{id}
POST   /api/v1/orders/{id}/cancel
GET    /api/v1/shifts?from=&to=&project_id=
POST   /api/v1/shifts/{id}/approve
GET    /api/v1/invoices?status=
GET    /api/v1/invoices/{id}/pdf
GET    /api/v1/documents?type=&from=&to=
POST   /api/v1/webhooks                          подписка
GET    /api/v1/me                                профиль, лимиты, уровень
```

### 3.10.4. Вебхуки
События: `order.created`, `order.confirmed`, `order.scheduled`, `order.cancelled`, `equipment.dispatched`, `equipment.arrived`, `shift.submitted`, `shift.approved`, `invoice.issued`, `invoice.overdue`, `partner.tier_changed`.

Доставка: POST с HMAC-подписью, ретраи 5 раз с экспонентой, журнал доставок в портале с возможностью ручной переотправки [M].

### 3.10.5. Технические требования
OpenAPI 3.1, интерактивная документация на `/api/docs` для авторизованных, песочница с тестовыми данными [S], курсорная пагинация, RFC 9457 для ошибок, `Idempotency-Key` для POST, rate-limit 600 запросов/мин на партнёра с заголовками `RateLimit-*`, версионирование с депрекацией за 6 месяцев.

## 3.11. Интеграция портала с диспетчерской Dimecon [M]

Портал бесполезен, если заявка из него «падает в почту». Требования к сквозному процессу:

| Событие в портале | Действие в бэкофисе | SLA |
|---|---|---|
| Создана заявка | попадает в очередь диспетчера с приоритетом по уровню партнёра | реакция 30 мин (раб. время) |
| Заявка срочная (< 24 ч) | звуковое оповещение + Telegram диспетчеру | 15 мин |
| Запрос переноса | задача диспетчеру, партнёр видит статус «рассматривается» | 60 мин |
| Оспорен рапорт | задача диспетчеру + уведомление начальнику парка | 4 ч |
| Партнёр у кредитного лимита | задача менеджеру и бухгалтеру | 1 раб. день |

**Требование [M]:** статус в портале всегда отражает реальность. Запрещены «висящие» статусы — по каждому статусу настроен таймаут, после которого создаётся задача ответственному и партнёр получает уведомление «мы работаем над вашей заявкой».
