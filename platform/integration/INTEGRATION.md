# Интеграция LiftPortal с экосистемой Artgranit / OfficePlus

Документ описывает, как платформа аренды спецтехники (LiftPortal) связана с вашей системой
на платформе **Artgranit** ([PavelTuhari/Artgranit](https://github.com/PavelTuhari/Artgranit),
production — `https://nufarul.eminescu.md/`, модули под `/UNA.md/orasldev/`).

Связь двусторонняя и реализована так, чтобы не нарушать инварианты обеих систем.

---

## 1. Что откуда берётся

| Направление | Что передаётся | Транспорт | Состояние |
|---|---|---|---|
| OfficePlus → LiftPortal | каталог товаров, остатки, изменения | Partner B2B API (`/product`, `/quantity`, `/changes`) | **реализовано**, покрыто 33 тестами |
| LiftPortal → OfficePlus | заказ товаров как счёт в ERP | `POST /order` (+ `validate_only`) | **реализовано** |
| Любая CRM → LiftPortal | контакты, компании, история сделок | выгрузка CSV/XLSX | **реализовано**, 24 теста |
| LiftPortal → портал Artgranit | витрина заявок, подач и парка | модуль `modules/liftportal/` + REST API LiftPortal | **реализовано**, требует установки в портал |
| Oracle ERP → LiftPortal | контрагенты и обороты напрямую из БД | `oracledb`, запросы по схеме ERP | **реализовано**, 28 тестов; нужен пароль |

## 2. Приём данных из OfficePlus

Клиент — `portal/services/officeplus.py`. Контракт взят из `docs/Partner/PARTNER_API.md`
исходного проекта: база `https://officeplus.md/api/v1`, реальные маршруты
`/UNA.md/orasldev/partner/api/…`, access-токен 1 час, refresh 30 дней, лимит 120 запросов в минуту.

**Что учтено из ваших же заметок о реальном поведении API** (раздел «Alte capcane» в PARTNER_API.md):

| Особенность реального API | Как обрабатывает клиент |
|---|---|
| `/product` отдаёт голый список без обёртки | `unwrap()` принимает и список, и `{data: […]}`, и `{items: […]}` |
| `product_name` приходит JSON-строкой `'{"ro":…}'` | `as_i18n()` разбирает строку, объект и простой текст |
| цены как `{amount, currency:{code, rate}}`, дилерская в USD | `as_money()` приводит к MDL: `amount × rate` |
| псевдонимы `ultra_code` / `ultra_uuid` | `pick()` принимает оба имени наравне с `code` / `uuid` |
| `sort=name_asc` отвечает 500 | клиент запрашивает `sort=updated_at` |
| 429 при превышении лимита | собственный троттлинг 120 запросов в минуту + пауза и повтор |
| истечение access-токена | при 401 гасится только access, refresh сохраняется и используется; вход по паролю — запасной путь |

Настройка — в кабинете компании: **Интеграция CRM → OfficePlus · Partner B2B API**.
Кнопки: проверить соединение, пробная синхронизация (без записи), синхронизировать каталог.

Перенесённые позиции создаются **скрытыми** (`is_published = false`) — их проверяет контент-менеджер.
Дилерская цена не публикуется: она хранится в атрибутах позиции. Сопоставление по артикулу,
повторная синхронизация обновляет, а не дублирует.

```bash
# проверка клиента на макете API, поднимаемом самим тестом
../.venv/Scripts/python tools/test_officeplus.py
```

## 3. Витрина LiftPortal внутри портала Artgranit

Каталог `integration/artgranit/liftportal/` — готовый модуль по контракту `docs/CORE_MODULES.md`:

```
modules/liftportal/
├── __init__.py      экспортирует blueprint с именем, равным ключу модуля
├── routes.py        страницы: сводка, заявки, парк, документация
└── module.json      манифест меню: название ru/ro/en, иконка, порядок, страницы
```

Соблюдены требования ядра:

- имя blueprint совпадает с ключом модуля (`liftportal`);
- маршруты объявлены **без** префикса — `/UNA.md/orasldev/liftportal` подставляет ядро;
- модуль не вызывает `app.add_url_rule` и `app.register_blueprint` (ядро их закрывает на время импорта);
- собственных Oracle-объектов модуль не создаёт, поэтому инвариант «рабочие данные — в Oracle»
  не нарушается: источником остаётся LiftPortal, портал показывает витрину по REST API;
- сбой связи не роняет страницу — выводится предупреждение.

### Установка

```bash
cp -r integration/artgranit/liftportal  /home/ubuntu/artgranit/modules/
cp -r integration/artgranit/docs_LiftPortal  /home/ubuntu/artgranit/docs/LiftPortal
cp  ../*.md ../docs/AKT_*.md README.md  /home/ubuntu/artgranit/docs/LiftPortal/
```

В `/home/ubuntu/artgranit/.env` добавить:

```
LIFTPORTAL_BASE=https://lift.example.md      # адрес платформы
LIFTPORTAL_API_KEY=<ключ из кабинета компании>
```

Затем `sudo systemctl restart artgranit`. Модуль появится в меню сам — по карте маршрутов,
без правок общего кода.

> Ваш production-инвариант соблюдён: модуль не трогает порт backend, `proxy_pass`, `WorkingDirectory`,
> virtualenv, `server_name` и пути SSL. После перезапуска проверьте
> `curl -I https://nufarul.eminescu.md/login` — ожидается `200 OK`.

## 4. Чтение контрагентов напрямую из Oracle

Адаптер — `portal/services/oracle_source.py`. Запросы построены не наугад, а по схеме,
которая используется в вашем же коде (`models/biro26_oracle_store.py`, `modules/partner/store.py`):

| Что читаем | Откуда |
|---|---|
| Контрагенты | `TMS_ORG o` + `TMS_UNIVERS u ON u.COD = o.COD AND u.TIP = 'O'` → `DENUMIREA`, `CODFISCAL`, `ADRESS`, `BANK`, `GR1` |
| Оборот по контрагенту | `VMDB_ST201D` + `TMDB_DOCS` (`SYSFID = 12280`) + `TMS_UNIVERS`, архивные (`ISARHIV='2'`) исключены |
| Учётные записи B2B | `PAPI_PARTNER` + связь с клиентом ERP через `UNIVERS_COD` |

Пагинация — по `ROWNUM`, как в исходном проекте: Oracle 11g не поддерживает `OFFSET/FETCH`.

**Важно про драйвер.** ERP работает на Oracle 11g, а thin-режим `python-oracledb` поддерживает
только 12.1 и новее. Поэтому в настройках по умолчанию выбран **thick-режим**, и на сервере
платформы понадобится Oracle Instant Client — путь к нему указывается там же. Для Autonomous
Database (портал Artgranit) подойдёт thin с указанием каталога кошелька.

Если структура у вас отличается, штатный запрос заменяется своим прямо в кабинете — колонки
`name / codfiscal / adress / gr1 / bank / cod` распознаются автоматически, пагинация добавляется сама.

Контрагенты переносятся в контакты платформы тем же конвейером, что и файловый импорт,
поэтому работает та же защита от дублей. Для выгрузок ERP, где нет телефона и почты,
сопоставление идёт **по фискальному коду, коду ERP и нормализованному названию компании**
(организационная форма — SRL, SA, ООО — при сравнении отбрасывается).

```bash
../.venv/Scripts/python tools/test_oracle_source.py   # 28 проверок на подставном соединении
```

Проверить живое подключение можно кнопкой «Проверить подключение» — она покажет версию СУБД,
режим драйвера и какие из ожидаемых таблиц доступны вашему пользователю.

## 5. Приём контактов из любой CRM

`portal/services/crm_import.py` + экран **Интеграция CRM**: загрузка CSV или XLSX, автоматическое
распознавание колонок по заголовкам (русским, румынским, английским), ручная правка сопоставления,
пробный прогон без записи, импорт с дедупликацией по нормализованному телефону и e-mail.
Опционально из суммы оборота создаётся история сделок в воронке.

## 7. Что потребуется от вас

| Сценарий | Что нужно | Где вводится |
|---|---|---|
| Контрагенты и обороты из Oracle | DSN, пользователь и **пароль** (он у вас на Mac); на сервере платформы — Oracle Instant Client для 11g | кабинет → Интеграция CRM → Oracle ERP |
| Синхронизация каталога | логин и пароль партнёра OfficePlus | кабинет → Интеграция CRM → OfficePlus |
| Витрина LiftPortal в портале | доступ к серверу для копирования модуля и перезапуска сервиса | `/home/ubuntu/artgranit/modules/` |
| Вебхуки «новый контакт / сделка» | настройка на стороне Artgranit: адрес приёма и общий секрет | — |

Пароли хранятся в настройках компании и в интерфейсе не показываются — поле пароля
остаётся пустым, отправка формы без него сохраняет прежнее значение.
