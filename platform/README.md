# LiftPortal — white-label платформа для компаний спецтехники

Многоарендная (multi-tenant) платформа на Flask по модели Airbnb: любое число компаний одного профиля (краны, негабаритные перевозки, монтаж) ведут бизнес через собственный кабинет, получают собственный сайт, CRM, B2C-подборщик техники с расчётом цены и портал партнёров B2B. Централизованы только сам портал и база данных; почтовый сервер, хранилище файлов и домен — у каждой компании свои.

Реализовано по ТЗ комплекта (тома 0–7) и дизайну макета Figma (`figma_Dimecon`: Manrope, navy `#1F3A52` + accent `#F5A623`, плотный портал / воздушный сайт).

## Быстрый старт

```bash
cd platform
python -m venv ../.venv
../.venv/Scripts/pip install -r requirements.txt      # Linux/macOS: ../.venv/bin/pip
copy .env.example .env                                # и отредактируйте DATABASE_URL
../.venv/Scripts/python run.py                        # http://localhost:8090
```

При первом запуске схема создаётся автоматически и заполняется демо-данными: три компании (`dimecon`, `macara-nord`, `sudlift`), парк техники с грузовыми таблицами, услуги, товары, кейсы, заказы в разных статусах, партнёр с проектом и сменами.

**Демо-доступы** (пароль `demo1234`):

| Логин | Роль | Куда попадает |
|---|---|---|
| `admin@platform.local` | суперадмин платформы | `/admin` — все компании, статусы, пакеты, журнал почты, DDL |
| `owner@dimecon.md` | владелец компании Dimecon 11 | `/s/dimecon/admin/` — кабинет с CRM |
| `partner@example.com` | партнёр B2B (Rezidential Grup) | `/s/dimecon/partner/` — проекты, заявки, рапорты |
| `client@example.com` | частный клиент | `/s/dimecon/account/` — заказы, повтор в 1 клик |

Смоук-тест всех ролей и сквозного визарда: `../.venv/Scripts/python tools/smoke.py`.

## MySQL

Основной режим — MySQL 8 через PyMySQL. Укажите в `.env`:

```
DATABASE_URL=mysql+pymysql://liftportal:secret@127.0.0.1:3306/liftportal?charset=utf8mb4
```

```sql
CREATE DATABASE liftportal CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'liftportal'@'%' IDENTIFIED BY 'secret';
GRANT ALL ON liftportal.* TO 'liftportal'@'%';
```

Таблицы создаются приложением при старте (`Base.metadata.create_all`). Готовый DDL для DBA: `python tools/export_ddl.py > schema_mysql.sql` или `/admin/ddl` из суперадмина.

**Если MySQL недоступен, платформа автоматически откатывается на SQLite** (`platform.db`) и пишет предупреждение в лог — так она запускается на любой машине без настройки.

**Текущий стенд работает на MySQL 8.4.0 LTS.** Сервер установлен в `D:\MySQL\mysql-8.4.0-winx64` (данные `D:\MySQL\data`, конфиг `D:\MySQL\my.ini`), база `liftportal` в `utf8mb4`. Запуск СУБД:

```bash
D:\MySQL\mysql-8.4.0-winx64\bin\mysqld.exe --defaults-file=D:\MySQL\my.ini
```

Результаты приёмки — в [акте тестирования](../docs/AKT_testirovaniya.md): 82 проверки, 52 скриншота, измерения производительности.

### Мультиарендность

Shared-schema: все данные компаний в одной БД, каждая строка помечена `tenant_id`; запросы фильтруются по `g.tenant`, права проверяются через `Membership` (одна личность может состоять в нескольких компаниях с разными ролями). Изоляция подтверждена тестом: владелец одной компании получает 403 в кабинете другой.

Компания определяется тремя способами (см. `tenancy.py`):

| Способ | Пример | Когда |
|---|---|---|
| Путь | `localhost:8090/s/dimecon/` | разработка, нет DNS |
| Поддомен | `dimecon.liftportal.md` | продакшн по умолчанию |
| Свой домен | `cranes.dimecon.md` | компания добавила домен в «Команда, домен, API» и направила A/CNAME на сервер платформы |

Для доменов WSGI-middleware переписывает путь на `/s/<slug>/…`, поэтому вся кодовая база одна.

### Что настраивает каждая компания сама (white-label)

- **Сайт и бренд**: название, реквизиты, контакты, слоган и «о компании» на трёх языках, цвета акцента и основы, логотип, фото героя, тёмная тема, FAQ, соцсети, языки и язык по умолчанию, валюта и НДС, показ в каталоге платформы.
- **Парк**: техника с ТТХ, грузовыми таблицами (вручную и CSV), тарифами единицы, фото (URL из любого хранилища), занятость (заказы, ТО).
- **Контент**: услуги, товары, кейсы, страницы — с переводами RU/RO/EN бок о бок; отзывы с модерацией и ответом.
- **Тарифы**: коэффициенты времени/сезона/условий/срочности, зоны подачи, допуслуги, скидки — JSON в кабинете; каждая строка расчёта показывается клиенту с названием.
- **Почта**: собственный SMTP (хост, порт, TLS/SSL, логин, от кого) с тестовой отправкой и журналом; без него — SMTP платформы; без обоих — письма сохраняются в журнал.
- **Хранилище файлов**: диск платформы / внешние ссылки (файл лежит где угодно) / S3-совместимое (нужен `boto3`).
- **Команда**: приглашения сотрудников с ролями, партнёров в портал; свой домен; API-ключ.
- **Интеграция с внешней CRM** (`/admin/integrations`): импорт контактов, компаний и истории сделок из выгрузки CSV или XLSX любой системы. Колонки распознаются по заголовкам на русском, румынском и английском; сопоставление правится вручную; дубликаты определяются по нормализованному телефону и e-mail, поэтому повторный импорт не плодит копий. Есть пробный прогон без записи. Обратный обмен — выгрузки Excel и REST API по ключу. Проверено 24 автотестами (`tools/test_crm_import.py`).

### CRM и процессы

- Заявка = лид + заказ: `stage` (new → contacted → quoted → won/lost) — канбан с drag-and-drop; `status` (submitted → … → paid) — исполнение. Смена статуса ведёт историю, подтверждение переводит мягкую бронь в жёсткую, отмена снимает бронь.
- Карточка заказа: параметры визарда, причины эскалации, журнал подборщика, показанный расчёт, назначение техники/ответственного/цены, выпуск документов (КП/подтверждение/акт/счёт) с отправкой клиенту, сменные рапорты.
- Контакты дедуплицируются по телефону/e-mail; при регистрации клиента старые заявки привязываются к кабинету.
- Портал партнёра: объекты, заявки из шаблона «как прошлая» и повторяющиеся по неделям, договорная скидка, график техники на 14 дней (чужие брони — без деталей), подтверждение/оспаривание рапортов, документы и лимит, прогресс уровня партнёрства.

## API

```
GET  /api/v1/health
GET  /api/v1/equipment           X-API-Key: <ключ компании>
POST /api/v1/quotes              {"equipment_id":3,"start":"2026-10-01T09:00","hours":4,"distance_km":12,"conditions":["rigger"]}
GET  /api/v1/orders
```

Ключ выпускается в кабинете («Команда, домен, API»); у демо-компаний — `demo-<slug>-key`.

## Продакшн

- `python run.py` запускает waitress (8 потоков). За ним — nginx с TLS; для поддоменов и своих доменов компаний nginx передаёт `Host` как есть (`proxy_set_header Host $host`).
- Обязательно задать `SECRET_KEY`, `PLATFORM_HOST`, `DATABASE_URL` (MySQL), при необходимости SMTP платформы как fallback.
- Файлы при `backend=local` лежат в `UPLOAD_DIR/<slug>/` и отдаются по `/media/<slug>/…`; для масштабирования компании переводятся на S3/CDN в своих настройках.
- Бэкапы — стандартные для MySQL (`mysqldump`), файловое хранилище — по выбору компании.
