# dimecon.md — главный файл проекта

Комплект технического задания на полное переписывание сайта **SA «Dimecon 11»** (Кишинёв) на Flask: публичный сайт, раздел самообслуживания для физических лиц (B2C) и портал партнёра (B2B).

**Текущая версия комплекта: 2.0** · дата 18.09.2026 · язык оригинала — русский.

**Референсы продуктовой модели:** маркетинговая часть — `odoo.com/industries/construction/general-contractor`; рабочий портал — `app.fieldwire.com`.

## 2. Правила именования файлов

> **Правило 1. В имени файла нет номера версии.**
> Имя документа постоянно на всём протяжении жизни проекта: `04_Uderzhanie_klienta.md` остаётся таким и в версии 2.0, и в 3.0. Это нужно, чтобы ссылки между документами, ссылки в задачах, в переписке и в буклете никогда не ломались.

> **Правило 2. Версия живёт внутри документа, а не в имени.**
> Первая строка каждого тома содержит номер версии комплекта: `# ТЗ v2.0 — Том 4. …`. Единый номер версии для всего комплекта хранится в `docs.json` (поле `version`) и в заголовке этого файла.

**Формат имени:** `NN_Kratkoe_nazvanie.md`, где `NN` — двузначный номер тома (`00`–`99`), далее транслитерированное название в `Snake_Case`. Кириллица, пробелы и спецсимволы в именах файлов не используются — они ломают ссылки, командную строку и веб-сервер.

**Примеры:**

```
00_Obzor_i_opcii.md          ✔ правильно
07_Figma_TZ.md               ✔ правильно
TZ_v2_04_Uderzhanie.md       ✘ версия в имени
04 Удержание клиента.md      ✘ кириллица и пробелы
04_Uderzhanie_final_v3.md    ✘ «final», «v3» в имени
```

## 3. Правила версионирования

> **Правило 3. Все старые версии переносятся в `backup/<номер версии>/`.**
> Подпапка называется по номеру версии, из которой файлы уходят: `backup/v1.0/`, `backup/v2.0/`, `backup/v2.1/`. Имена файлов внутри архива — те же, без версии.

**Структура:**

```
dimecon.md/
├── README.md                    ← главный файл, текущая версия
├── 00_Obzor_i_opcii.md          ← актуальные документы (без версии в имени)
├── …
├── 07_Figma_TZ.md
├── index.html                   ← буклет
├── docs.json                    ← манифест
└── backup/
    ├── v1.0/
    │   └── TZ_ramochnoe.md      ← рамочное ТЗ версии 1.0
    └── v2.0/                    ← появится при переходе на 3.0
```

### Процедура выпуска новой версии

1. Скопировать **все** актуальные `*.md` в `backup/v<текущая версия>/` — целиком, а не выборочно: архив должен быть консистентным срезом.
2. Внести правки в актуальные файлы (имена не меняются).
3. Поднять номер версии в трёх местах: заголовок каждого тома (`# ТЗ v3.0 — Том N …`), поле `version` в `docs.json`, шапка этого файла.
4. Добавить запись в журнал изменений (§6).
5. Если появился новый том — добавить его в `docs.json`, в таблицу §1 и в §0.1 Тома 0.

**Правило 4. Файлы в `backup/` не редактируются.** Архив — только чтение. Если в старой версии обнаружена ошибка, она исправляется в актуальной версии, а не задним числом в архиве.

**Правило 5. Версия повышается по существу изменений:**

| Изменение | Версия |
|---|---|
| Опечатки, переформулировки, уточнения без изменения объёма работ | не меняется, правка на месте |
| Добавлен раздел, уточнены требования, изменены цифры | минорная: 2.0 → 2.1 |
| Изменён объём, состав томов, принятые развилки, архитектура | мажорная: 2.х → 3.0 |

## 4. Хаб документации

`index.html` — единая точка входа ко **всем** файлам проекта, а не только к ТЗ: обложка со сводкой, разделы слева, сквозной поиск по содержимому, печать/PDF, светлая и тёмная темы, перевод.

**Всё открывается прямо в странице:**

| Тип файла | Как показывается |
|---|---|
| `.md` | вёрстка Markdown с таблицами, ссылки между документами и картинки работают |
| `.log`, `.txt` | моноширинный вывод с подсветкой: зелёным `ok`, красным ошибки и `Traceback` |
| `.json` | форматированный отступами |
| `.py`, `.sql`, `.css`, `.js` | исходный код |
| `.html` | живой просмотр в рамке + переключение на исходник |
| `.png`, `.jpg` | просмотр с увеличением по клику; для скриншотов — галерея с подписями |
| `.pdf` | встроенный просмотрщик браузера |
| `.xlsx` | разбирается в браузере: вкладки листов и таблица данных |

**Файлы подгружаются на лету.** Страница читает `manifest.json` и затем сам файл — копий не хранит. После добавления или изменения файлов достаточно пересобрать манифест:

```bash
python tools/build_manifest.py
```

Скрипт обходит проект, раскладывает файлы по разделам, подтягивает подписи скриншотов и считает сводку. Правка `index.html` при этом не нужна.

### Как открыть

**Двойной клик по `start.bat`** — поднимаются MySQL, хаб документации и платформа, окна серверов сворачиваются в панель задач, браузер открывается сам:

| Что | Адрес |
|---|---|
| Документация | `http://localhost:8080` |
| Платформа | `http://localhost:8090` |
| Сайт компании Dimecon 11 | `http://localhost:8090/s/dimecon/` |
| Кабинет | `owner@dimecon.md` / `demo1234` |

Остановить — `stop.bat` (спросит отдельно, гасить ли MySQL). Скрипты идемпотентны: если порт уже занят, сервер не поднимается повторно.

Вручную, если нужно только чтение документации:

```bash
python -m http.server 8080
```

Браузеры запрещают странице, открытой напрямую с диска (`file://`), читать соседние файлы — поэтому локальный сервер обязателен.

> Оба `.bat` — тонкие обёртки над `start.ps1` / `stop.ps1`. Сами PowerShell-скрипты сохранены **в UTF-8 с BOM**: Windows PowerShell 5.1 без BOM читает файл как cp1251, и русский текст ломает разбор. При редактировании сохраняйте кодировку.

### Добавление файлов

Просто положите файл в проект и пересоберите манифест — он появится в нужном разделе. Разделы и правила раскладки заданы в `tools/build_manifest.py` (список `GROUPS` и функция `group_of`); человеческие названия документов — в словаре `DOC_TITLES`.

### Горячие клавиши

| Клавиша | Действие |
|---|---|
| <kbd>/</kbd> | перейти в поиск |
| <kbd>Esc</kbd> | закрыть поиск или панель перевода |

## 5. Язык и перевод

> **Правило 6. Источник правды — один язык: русский.**
> Переводы документов не хранятся и не поддерживаются вручную — иначе версии неизбежно разъезжаются, и никто не знает, какая из них актуальна. Читать на другом языке следует через движок перевода браузера.

Страница подготовлена для корректного машинного перевода:

- у документа выставлен `lang="ru"` — Chrome, Safari и Edge сами предлагают перевод;
- содержимое — обычный текст в DOM, доступный переводчику (не картинки и не canvas);
- блоки кода, SQL, названия таблиц и полей помечены `translate="no"` — они не искажаются переводом;
- кнопка **🌐 Язык** в шапке: если браузер поддерживает встроенный API перевода (Chrome 138+), перевод выполняется прямо на странице, локально на устройстве, с кнопкой возврата к оригиналу; если нет — панель показывает, как вызвать перевод средствами самого браузера.

**Как перевести средствами браузера:**

| Браузер | Действие |
|---|---|
| Chrome / Edge | правый клик по странице → «Перевести на…» либо значок перевода в адресной строке |
| Safari | значок перевода в адресной строке → «Перевести на…» |
| Firefox | меню перевода в адресной строке (встроенный локальный перевод) |

После переключения тома перевод нужно применить повторно — содержимое загружается динамически.

**Важно:** машинный перевод годится для чтения и понимания. Юридически значимые формулировки (оферта, договор, SLA) и тексты интерфейса будущего сайта переводятся отдельно человеком — это отдельная работа, описанная в Томе 0 §0.10 и Томе 7 §7.11.

## 6.1. Демо-стенд на eminescu.md

Проект развёрнут на демо-хостинге в выделенном слоте `TehnCons`.

| Что | Адрес |
|---|---|
| Витрина платформы | https://eminescu.md/TehnCons/ |
| Сайт заказчика | https://eminescu.md/TehnCons/s/dimecon/ |
| Подбор техники и расчёт | https://eminescu.md/TehnCons/s/dimecon/calculator |
| Документация проекта | https://eminescu.md/TehnCons/docs/ |
| Акты тестирования | https://eminescu.md/TehnCons/docs/docs/acts/index.html |
| Презентация | https://eminescu.md/TehnCons/docs/docs/presentation.html |

Вход демо-ролями — кнопками на странице входа: клиент, партнёр B2B, компания, платформа.

Параметры слота заданы контрактом хостинга и не меняются: порт 3005 (только localhost),
каталог `/var/www/eminescu/TehnCons`, служба `tehncons.service`, префикс пути `/TehnCons/`,
владелец файлов `opc:opc`. В nginx добавлены только блоки `location /TehnCons/…`;
конфигурация правится после резервной копии и проверки `nginx -t`.

На демо-стенде MySQL не требуется: пакет содержит готовую базу SQLite со всем перенесённым
содержимым сайта заказчика. Пересобрать и обновить:

```bash
python tools/build_deploy.py                 # собрать пакет в dist/TehnCons
scp -r dist/TehnCons/* opc@СЕРВЕР:/var/www/eminescu/TehnCons/
ssh opc@СЕРВЕР 'sudo systemctl restart tehncons'
```

Приложение умеет жить в подкаталоге чужого домена: префикс задаётся переменной `URL_PREFIX`
(см. `platform/.env.example`), снимается посредником `platform/portal/hosting.py` и попадает
во все ссылки, редиректы и путь cookie.

## 7. Что требуется от заказчика до старта разработки

Полный список — Том 0 §0.10. Критический путь:

1. **Паспорта ГПМ с грузовыми таблицами** — без них не работает ядро подборщика техники. Сбор начинается в первую неделю.
2. **Протокол по 20 развилкам** (Том 0 §0.6) — иначе разработка будет останавливаться на вопросах.
3. **Действующие тарифы, коэффициенты, зоны обслуживания** — без них не запускается калькулятор.
4. **Владелец продукта со стороны заказчика** — не менее 4 часов в неделю.
5. **Контент-ответственный** — редактура и перевод текстов RO/RU/EN.
